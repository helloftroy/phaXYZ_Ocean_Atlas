# PHA Gene Family Atlas: Verified Results

This document covers the ocean-metagenome PHA (polyhydroxyalkanoate) pathway gene search — 15 gene families, searched against a global ocean gene catalog, with every recruiting reference sequence individually verified against UniProt and InterPro before being counted. It documents the current, verified state of the dataset going forward.

## 1. Setup

### 1.1 Reference sequences: how each family's search bait was assembled

Each of the 15 PHA pathway gene families (phaA, phaB, phaC, phaD, phaE, phaF, phaG, phaI, phaJ, phaP, phaQ, phaR_regulator, phaR_synthase, phaY, phaZ) is defined in `config/family_definitions.yaml` by: its known UniProt gene-name aliases (e.g. phaA/phbA), a set of free-text protein-name search phrases (e.g. "acetyl-CoA acetyltransferase," "acetoacetyl-CoA reductase"), and — where the family has one — a BRENDA EC-number seed (e.g. phaA=EC 2.3.1.9, phaB=EC 1.1.1.36). Two families that share the literal gene name "phaR" for genuinely different proteins — the class III/IV PHA synthase small subunit (phaR_synthase) and the PHA-responsive transcriptional autorepressor (phaR_regulator) — are kept as deliberately separate families, disambiguated by required co-occurring text (phaR_synthase requires "synthase"/"class IV"/"PhaRC" context; phaR_regulator requires "regulator"/"repressor"/"transcriptional" context).

Candidate sequences were pulled from BRENDA (by EC number, where applicable) and UniProt (by gene name and protein-name phrase), then reduced to non-redundant representatives at 95% identity / 90% coverage (`mmseqs easy-cluster --min-seq-id 0.95 -c 0.90 --cov-mode 0`) — one query FASTA per family, headers carrying only the protein accession.

### 1.2 Target database

The search target is **OMDBv2.0_AA_G_NR100** — the Ocean Microbiomics Database's amino-acid gene catalog, dereplicated to 100% identity. Target IDs throughout this project (e.g. `OMDBv2.0_AA_G_NR100_000103673917`) trace directly to entries in this catalog, each ultimately resolvable back to a specific metagenome-assembled genome (MAG) or isolate genome, its GTDB taxonomy, and its sample's collection metadata (location, depth, ecosystem type).

### 1.3 Search

Each family's query set was searched against the target database with MMseqs2 (GPU-accelerated build):

```
mmseqs search <query_db> <omdb_target_db> <result_db> <tmp> \
    -s 7.0 -e 1e-5 -c 0.0 --max-seqs 10000 --alignment-mode 3 --gpu 1

mmseqs convertalis <query_db> <omdb_target_db> <result_db> <hits.tsv> \
    --sub-mat aa:blosum62.out --format-mode 4 --translation-table 1 \
    --gap-open aa:11 --gap-extend aa:1 \
    --format-output query,target,evalue,bits,pident,alnlen,qstart,qend,qlen,tstart,tend,tlen,qcov,tcov
```

Sensitivity 7.0 (MMseqs2's most sensitive setting) and coverage 0.0 at search time were deliberate: coverage is filtered downstream per-analysis rather than at the alignment step, so fragmentary hits (partial gene calls, contig edges — common in MAG data) aren't silently discarded before they can even be evaluated. Every family's target hits were then collapsed to one row per target (`<family>_unique_targets_with_metadata.tsv`): the best-scoring reference match (`best_query`), its identity/coverage/E-value, and the target's resolved genome/taxonomy/sample metadata.

### 1.4 Cross-referencing every reference for accuracy

Before any hit was counted, the reference sequence that recruited it (`best_query`) was independently verified — not assumed correct because it originated from the curated BRENDA/UniProt retrieval above. For every one of the roughly 9,600 distinct reference sequences that ever recruited a hit across all 15 families:

1. **UniProt annotation retrieved directly** (protein name, organism, sequence length) — not taken from the original retrieval's own labeling, which turned out to be unreliable for a meaningful share of references (a real, recurring bacterial gene-naming collision: a multi-subunit ion-transport operon, unrelated to PHA metabolism, happens to also be historically abbreviated "Pha" with subunits lettered A–G, colliding one-for-one with this project's own phaA–phaG gene names).
2. **InterPro/Pfam domain composition checked for every reference, not just a sample** (not name text alone) — this is the step that catches a reference whose *name* looks right but whose actual domain architecture doesn't match. Each of the ~9,600 references was resolved to its full InterPro match set and checked against a confirmed-good marker-domain signature for its family (e.g. IPR011283 specifically for phaB's acetoacetyl-CoA reductase, IPR002155 for phaA's thiolase fold, IPR010134 for the real PhaR autorepressor) and against a confirmed-bad list of unrelated domain families (AraC-type regulators, the antiporter-subunit domains, phenylacetate-pathway enzymes, polyketide/fatty-acid synthase domains, and others). This caught references with generic, non-specific names (e.g. "PhaR protein," "PhaD protein," "PhaF2 protein," even one literally named "Pesticidal protein Cry1Ba") that were, on inspection, a structurally unrelated protein family wearing a misleading label — and, in the other direction, recovered several genuine references that generic wording alone hadn't confidently matched.
3. **Cross-checked against this project's own `config/family_definitions.yaml`** identity for that family, so a real PHA-pathway protein recruited under the *wrong* family (e.g. a genuine depolymerase reference filed as phaD) was also caught, not just outright non-PHA contamination.

References that failed this check were added to an exclusion list (`FAMILY_BAD_QUERIES` in `phaatlas/pipeline/pathway_architecture.py`) and every target they recruited was removed from that family's counts. The genome × gene-family matrix and every count in this document reflect that corrected, verified reference set.

## 3. phaC evidence tiers: catalytic triad, HMM, and verified pathway context

**Rebuilt 2026-09-22 against the corrected 31,464-genome phaC set (§2).** For all 31,464 verified phaC genomes, five evidence tiers were built, strongest evidence first and mutually exclusive:

1. **Catalytic triad complete** — the Cys-Asp-His catalytic triad (confirmed via P23608/Cupriavidus necator PhaC1 numbering: Cys319 in a G-x-C-x-G lipase-box-like motif, Asp480, His508) is present at all three expected positions, located by projecting every target onto the project's own 625-column PhaC profile HMM via `hmmalign`.
2. **HMM-supported (no triad)** — hits at least one of 6 independently-built PhaC profile HMMs (Pfam PF07167, this project's own 822-sequence model, NCBIFam TIGR01838/01839/01836 for Class I/II/III, PANTHER PTHR36837) but the triad wasn't resolvable (usually because the alignment doesn't reach that far — see below).
3. **No HMM/triad, ≥5 other PHA genes** — no direct protein-level confirmation, but the genome carries 5 or more *other, individually verified* PHA pathway genes (§1.4's reference audit applied to every family, not just phaC).
4. **No HMM/triad, 1–4 other PHA genes** — same, with fewer supporting genes.
5. **phaC only** — no HMM hit, no triad, and no other verified PHA pathway gene in the genome at all.

**This is a dramatically different picture than the pre-fix version of this table** (which read 42.0% / 5.5% / 6.8% / 43.9% / 1.8%). The three weak-evidence tiers — which together held 52.5% of the dataset before the phaC reference-query fix (§2) — have collapsed to 27 genomes total (0.09%), and the strong-evidence tiers now cover 99.9% of the dataset. This is not a coincidence or a methodology change: it is the direct, mechanical consequence of removing 152 phaC reference queries that lacked the real PHA-synthase domain. A genome whose only "phaC evidence" was a weak partial match to one of those misannotated/fusion references never had real HMM or triad support to begin with — removing that genome from the dataset doesn't change its tier, it removes exactly the kind of case that used to populate the weak tiers. **The entire premise of §6 (structure prediction to resolve tiers with no direct evidence) is now moot at its original scale** — there are 27 such genomes left, not the ~35,900 (52.5%) the structure-prediction pipeline was built to handle. ## 4. Sequence evidence against the full audited reference set

**Rebuilt 2026-09-22 against the corrected candidate and reference sets.** Every verified phaC target was searched against all 1,723 audited references (down from 1,875 — all 152 accessions excluded by §2's phaC fix were themselves part of this reference set, confirmed by direct header comparison; this needed correcting on both sides, not just the candidate side) with MMseqs2 (`-s 7.0 -e 1e-5 -c 0.0`), and reduced to its single best hit by bit score. Reused the existing raw mmseqs2 hits table rather than re-running the search — verified that filtering it on both the corrected query side and the corrected reference side is equivalent to having searched against a clean reference set from the start (`catalytic_domain/build_sequence_evidence_table.py`). For each of the 33,780 verified targets with a surviving hit this gives: protein length, the matched reference's own accession and length, %identity, alignment length, E-value, query/target coverage, and the query-to-reference length ratio — the full table is `catalytic_domain/phac_sequence_evidence.tsv`.

What can still be said: both tiny tiers keep reasonable query coverage (85.2% each) and non-trivial identity (36-51%, actually *higher* than either tier managed pre-fix), and their target coverage is low (22-34%) for the same reason the HMM-supported tier's is (43-shorter candidates relative to typically ~800aa references, likely genuinely partial gene calls) — consistent with real-but-fragmentary calls rather than a flag for further suspicion, but this is now a statement about 23 individual genomes, not a dataset-wide trend.

### 6.1 Scale and approach

Folding all 68,424 verified genomes individually would mean predicting ~48,000 structures for the three unresolved tiers alone — a real undertaking even on a GPU cluster. Deduping to one representative sequence per phaC_cluster0.7 cluster (70%-identity groups) cuts this to a much more tractable **4,992 sequences** (one per cluster touched by an unresolved-tier genome, length-filtered to 150-700aa to exclude obvious fragments) — clusters, not genomes, are the natural unit here anyway, since near-identical sequences within a cluster would fold near-identically. Combined with a **428-sequence positive-control sample** (stratified by phylum, drawn from clusters touched only by triad-complete/HMM-supported genomes — confirms the whole ESMFold→Foldseek approach actually recovers the right answer on cases already known to be real, before trusting it on the uncertain ones) and the **1,875-sequence audited reference set** (§1.4/§4 — these get folded too, to serve as the Foldseek comparison targets, built from the same verified pool as everything else in this project rather than an arbitrary external structure database), the total scope is **~7,300 structures**. That's a reasonable scale for ESMFold on a single GPU node — not an AlphaFold2/ColabFold-scale undertaking, which is exactly why ESMFold (a single forward pass, no MSA search, seconds-to-low-minutes per structure) is the right first tool rather than starting with the slower, MSA-dependent alternatives.

### 6.2 Pipeline

- `structure_prediction/build_fold_inputs.py` — builds the three FASTA sets described above from the same verified-tier data as §3 (`/tmp/phac_verified_triad_hmm_group.pkl`, `/tmp/verified_phac_genome_targets.pkl`) plus the cluster assignment table. Deterministic (fixed random seed) so the positive-control sample is reproducible.
- `structure_prediction/run_esmfold.py` — the folding driver. Uses HuggingFace `transformers`' `EsmForProteinFolding` rather than Meta's original `fair-esm[esmfold]` package deliberately: the original needs `openfold`'s custom CUDA attention kernels compiled against the exact local CUDA/PyTorch build, a common source of cluster-install pain; the `transformers` port reimplements the same model in plain PyTorch with no custom kernel step. Writes one PDB file per sequence plus a summary TSV (length, mean pLDDT, pTM, status). Resumable — skips any target_id whose PDB already exists, so a retried/re-submitted array task only fills gaps.
- `cluster/install_esmfold.sh` — environment setup. Adds ESMFold's packages (torch, transformers, accelerate, einops) to the *existing* `pha-reference` env (the one `source cluster/env_activate.sh` activates) rather than creating a separate one — only 4 new packages, not enough to justify a second env and a second activation step in the normal workflow. Every installed file is placed via `pip install --target=` onto scratch (`/scratch/morrill/users/hmp278/esmfold_packages`, not the env's own site-packages under `$HOME`) and imported into the existing env via a generated `cluster/esmfold_pythonpath.sh`. Model-weight cache (`$HF_HOME`, ~2.7GB) and the pip download cache also default to that same scratch path.
- `cluster/run_esmfold.sbatch` — SLURM array job, one task per batch slice of one input FASTA; run once per input file (uncertain / positive-control / reference). Sources `cluster/env_activate.sh` + the generated `esmfold_pythonpath.sh`.

**Two real install bugs found and fixed live** (worth knowing before the same class of issue reappears with ColabFold below): (1) `pip install --target` *silently skips* any file that already exists unless `--upgrade` is passed — a second install attempt left a broken mix of old and new package files; `install_esmfold.sh` now wipes the target directory clean before every run. (2) An unpinned `transformers>=4.35` resolved to `5.17.0` — a major version with breaking API changes relative to the `4.x` line this pipeline was written against — which failed importing ESMFold with a `torch.distributed.fsdp` `ImportError`; pinned to `transformers==4.44.2`. Also dropped a stale hardcoded `--index-url .../cu121` for PyTorch — a plain `pip install torch` on this cluster already resolves a CUDA-enabled build with its own bundled runtime.

**GPU nodes have no internet:** `install_esmfold.sh` now actually downloads the ~2.7GB `facebook/esmfold_v1` weight checkpoint on the login node (into `$HF_HOME` on scratch) as part of the install itself, rather than leaving that as a follow-up suggestion — the weights need to already be cached before a GPU job can use them. `run_esmfold.sbatch` sets `HF_HUB_OFFLINE=1`, so if that caching step ever got skipped, the job fails immediately with a clear "not in cache" error instead of hanging while trying to reach `huggingface.co` from a node that can't.

### 6.3 Foldseek and ColabFold: installed, not yet run

- `cluster/install_foldseek.sh` — static binary install, same distribution model as `cluster/install_mmseqs2.sh` (same lab, same prebuilt-GitHub-release-tarball approach) — no conda env, no Python, nothing to pip-install. Installs to `cluster/bin/foldseek`.
- `structure_prediction/run_foldseek_search.sh` — builds a Foldseek database from the folded reference structures, then searches the uncertain-tier and positive-control structures against it (`easy-search`, TM-align mode for a direct TM-score). Deliberately loose (`-e 10`, `--max-seqs 2000`) rather than Foldseek's tighter default: at this stage we specifically want every candidate's best hit reported even if weak, not silently dropped from the output for scoring below a threshold — dropping weak hits would bias the "where should the cutoff go" distributions in §6.3.5 toward looking better than reality. Needs real `.pdb` output from the ESMFold jobs first; not runnable yet.
- `structure_prediction/build_structural_evidence_table.py` — collapses that raw, multiple-hits-per-query Foldseek output into one best-hit row per candidate (ranked by highest `alntmscore`, ties broken by bits), with columns `candidate_id, group, status, best_reference, qtmscore, ttmscore, alntmscore, aligned_length, qcov_struct, tcov_struct, structural_pident, evalue, bits, prob`. Cross-checks against `fold_manifest.tsv` (the full candidate list) so candidates with **no** hit at all — even at the loose `-e 10` above — still get an explicit `status=no_hit` row instead of silently vanishing from downstream counts. Dry-run tested against synthetic data end-to-end (real `.pdb`s don't exist yet) to confirm the best-hit selection and no-hit accounting both work correctly.
- `figures/scripts/plot_structural_evidence_violins.py` — six-panel violin comparison (qtmscore, ttmscore, alntmscore, structural %identity, query/target structural coverage), positive controls vs. uncertain tier, styled like §4's sequence-evidence violins. Reports each group's no-hit count in the subtitle rather than only plotting the candidates that got a hit. No cutoff line is drawn — see §6.3.5.
- `cluster/install_colabfold.sh` — a **dedicated** conda env on scratch (`/scratch/morrill/users/hmp278/conda_envs/colabfold`), deliberately *not* added to the shared `pha-reference` env the way ESMFold was: ColabFold pulls in JAX plus a pinned AlphaFold fork (haiku, dm-tree, a jax/jaxlib build tied to the local CUDA version) — a much larger, more version-sensitive dependency tree, and a poor fit for an env other work depends on. Uses this project's existing miniforge3 install, just a new env prefix under it. ColabFold over raw AlphaFold2 specifically because AlphaFold2's own database-search path needs ~2.2TB of downloaded genetic databases — disproportionate to this project's actual need (a few hundred to a few thousand "hard" cases). ColabFold's MSA generation defaults to a free remote API (api.colabfold.com) instead, so no local sequence database download is needed for a first pass; structure inference still runs locally on GPU.
- `cluster/run_colabfold.sbatch` — job template for later use on the *escalation subset only* (candidates ESMFold handled poorly or Foldseek left ambiguous), not the full ~7,300-sequence set — that scale distinction is the whole reason for doing the cheap ESMFold pass first.

**Same honest caveat as ESMFold:** none of the Foldseek/ColabFold scripts have been run live yet either. JAX's CUDA-version sensitivity is a well-known common source of ColabFold install friction specifically (not just this project's own uncertainty) — expect at least one more round of pasting an error back, the same way ESMFold needed two.

### 6.3.5 Rescue cutoff: not chosen yet, on purpose

The point of this whole structural check is to answer "does the fold look like a real PhaC," and the honest way to answer that is to look at where positive controls and uncertain candidates actually land on `qtmscore`/`ttmscore`/`alntmscore`/structural %identity *before* picking a threshold — not decide a round-number cutoff (e.g. "TM-score > 0.5") in advance and hope the data cooperates. `plot_structural_evidence_violins.py` exists to make that comparison directly. Read for: (a) do positive controls cluster tightly high, confirming the pipeline itself works; (b) does the uncertain tier show a bimodal split (some candidates as confident as the positive controls, others much lower) rather than a smooth continuum — a visible split point is a far more defensible cutoff than an arbitrary one; (c) what fraction of each group got **no hit at all** even at the loose `-e 10` search threshold, since that's itself part of the answer (a candidate with zero structural hit against 1,875 references is a very different case from one that hit something with a mediocre score).

## 8. mcl-PHA precursor supply: the FAS-linked route (phaG) vs. the beta-oxidation-linked route (phaJ)

**Rebuilt 2026-09-22 against the corrected 31,464-genome phaC set.** A genome with phaC alone can make scl-PHA (via the canonical phaA+phaB route: acetyl-CoA condensed into (R)-3-hydroxybutyryl-CoA), but mcl-PHA needs a different, longer precursor, and there are two independent gene routes to it: `phaJ` ((R)-specific enoyl-CoA hydratase) is the **beta-oxidation-linked route** — it diverts an intermediate out of beta-oxidation, of fatty acids from the environment or a host — while `phaG` (3-hydroxyacyl-ACP:CoA transacylase) is the **fatty-acid-synthesis-linked (FAS-linked) route** — it connects the genome's own fatty-acid-synthesis pathway directly to PHA synthesis, pulling a monomer from there instead of from external fatty acid breakdown. The beta-oxidation-linked route is normally cheaper to run when fatty acids are available to break down, so a habitat or lineage leaning on phaG specifically is a plausible signal that fatty acids simply are not available there to break down — a lipid-poor niche. `figures/scripts/plot_phac_mcl_precursor_strategy.py` maps this onto full pathway architecture, then asks whether taxonomy or habitat drives the choice (`figures/phac_mcl_precursor_strategy.png`).

**phaG is still rare and still mostly an add-on, not a replacement for phaJ — though somewhat less rare than before.** Full architecture: ABJ 57.0% (17,944), AB-only 23.4% (7,361), phaC-only 10.4% (3,267), ABGJ 4.3% (1,363), J-only 3.7% (1,173), ABG 0.9% (270), G-only 0.2% (53), GJ 0.1% (33). **Taxonomy:** phaG usage still varies widely by phylum (≥200 phaC-positive each, `figures/phac_mcl_strategy_by_phylum.tsv`): Actinomycetota 9.0% (n=586), Pseudomonadota 5.9% (n=26,798, dominant phylum), Desulfobacterota 3.3% (n=337), Myxococcota 2.7% (n=337), down to SAR324 0.9% (n=540). Algae thallus and sea ice remain significantly elevated, though less strongly than before (OR 2.21→1.62, 2.07→1.84). A genuinely new significant result appears: **hydrothermal vent fluid/plume is now elevated** (OR 2.40, p=0.007) — not flagged at all in the earlier pass. **Seawater**, the dominant background category, is now also significantly elevated (OR 1.35, p=2×10⁻⁵) — a small effect size but the huge n makes it statistically solid; read this as "not really a meaningful habitat effect for the default bucket," the same way §5.3.1 treats seawater's other results. **What has stayed completely consistent across both passes: the two host-associated animal-tissue habitats remain significantly and strongly *depleted* for phaG** — sponge tissue (OR 0.51→0.44, p=2.2×10⁻⁸) and hydrozoa tissue (OR 0.26→0.09, p=2.9×10⁻⁵, now even more depleted) — both showing very high phaJ instead (84.0%, 86.8%). That depletion in exactly the habitats where scavengeable host lipids should be most abundant is the part of the lipid-availability hypothesis with the most consistent support across both corrections; the "which specific oligotrophic habitats show elevation" side of the story is less stable and should be held more loosely.

### 9.1 Deep dive: the ≥5-copy tail (`figures/phac_high_copy_deep_dive.png`)

**≥2 copies is common (37.7%, above); ≥5 is the genuinely unusual case this subsection asks about specifically.** 239 of 31,464 phaC-positive genomes (0.76%) carry 5 or more copies. Four questions, in order:

**Do a few species account for most of them? No.** The 239 genomes span 145 distinct species; the top 5 species account for only 41 of them (17.2%) — not a small-species story. The single largest species contributor, *Legionella pneumophila* (20 genomes, 8.4% of the tail), is a red herring for a different reason (next paragraph). What actually structures this tail is **site, not species**: four studies — `CARD22-1` (Red Sea coral tissue), `CHAS20-1` (Tahiti/Moorea sediment), `DONG22-1` (South China Sea sediment), and `CAOS20-1` (Southern Ocean seawater) — show 3-5.5× the dataset-wide ≥5-copy rate (2.3-4.2% vs. 0.76% overall), and within each study the elevated genomes span **33 to 93 distinct genera** (`figures/phac_high_copy_by_study.tsv`) — dozens of taxonomically unrelated lineages all showing elevated copy number at the same site, not one expanding lineage.

**Are we sure all their phaC calls are legit? Mostly, but weaker than first reported here — a real measurement bug was found and corrected while following up with a Legionella-specific deep dive (see below).** Using the corrected NR100 target_id↔genome join (not `phac_sequence_evidence.tsv`'s own `genome` column, which names only one arbitrary genome per NR100-deduplicated target_id and silently misses the rest — the same confound flagged in §9's own script docstring) still gets every individual copy correctly attributed to its own genome, but this section originally read per-target legitimacy off `phac_sequence_evidence.tsv`'s `evidence_tier` column, and that column turns out not to be a per-target measurement at all: per `catalytic_domain/build_sequence_evidence_table.py`, it is each GENOME's *best* tier, broadcast onto every target belonging to that genome. For a single-copy genome that's harmless. For a multi-copy genome it means one truly triad-complete copy is enough to label *every* copy of that genome "Catalytic triad complete," including copies with zero of the three catalytic residues — exactly the population this section is about. Re-checked against `catalytic_domain/phac_catalytic_triad.tsv`'s own per-target `triad_complete` column, the **true rate is 71.6% (716/1,000 distinct target_ids)**, not 98.8% — still a majority, but a meaningfully weaker legitimacy bar than first reported, and the dataset-wide §4 table is very mildly inflated by the same mechanism (89.5% of targets it tags "Catalytic triad complete" are actually complete at the per-target level — small overall since most of the dataset is single-copy, where the bug has no effect). Contamination for the MAG-derived high-copy genomes is modestly elevated (mean 2.16% vs. 1.53% dataset-wide) but nowhere near typical MAG-quality-failure territory (max 9.55%). Within a genome, its own copies are usually clearly divergent from each other (median 74.9% pairwise identity; only 3.3% of comparable pairs ≥95% identical) — the opposite of the near-100%-identical signature a simple assembly-duplication artifact (the same gene mis-called twice) would leave. But the taxonomic-diversity pattern above — dozens of unrelated genera all elevated at the same four sites — is exactly the shape a shared technical effect (e.g. strain heterogeneity in a co-assembly causing spurious extra gene calls across many bins from one sample) would produce, and is a less parsimonious fit for "dozens of unrelated lineages independently evolved multi-copy phaC at the same reef/sediment/water sample." **Left as an open question, not resolved either way** — distinguishing the two would need re-examining those specific samples' assemblies directly, out of scope here. (§9.2 below shows a second, independently checkable mechanism for the same "is it legit" question in isolate genomes specifically: NCBI's own per-assembly quality flags.)

**Where in the world?** 92/239 (38.5%) are `RSGB23-1` genomes — a bulk NCBI RefSeq isolate-genome import with **no habitat or location metadata for any of its 12,683 genomes** (confirmed directly, not just missing for this subset) — these cannot be placed geographically or ecologically at all, and *Legionella pneumophila*, an intracellular pathogen with no plausible marine sampling context, is entirely a product of this batch (all 20 of its genomes are RSGB23-1). Of the remaining 147 located, MAG-derived genomes: the single most concentrated site is Southern Ocean seawater off the Antarctic Peninsula (`CAOS20-1`, one site, 15 genomes across 7+ genera), followed by a Red Sea reef site carrying both `CARD22-1`'s coral-tissue genomes and `WANG22-1`'s biofilm genomes at essentially the same coordinates (~9 genomes combined), Gulf of Mexico sediment (`ATLA15-1`, 6 genomes), and a Darwin, Australia seawater site (`BPAM22-1`, *Bradyrhizobium denitrificans* — 3 near-identical genomes each with 10 copies, this dataset's maximum).

**Which habitats and species?** Among the 147 located genomes: seawater dominates (95, 65%), then marine sediment (26, 18%), with marine biofilm, coral tissue, sponge tissue, and sea ice each contributing a handful. Taxonomically, most of the tail is **unnamed/novel GTDB lineages** (placeholder genus codes like `UBA1479`, `JAKSBE01`, `CANJQJ01`) rather than well-characterized reference species — consistent with this extreme tail being concentrated in under-studied taxa. Among recognizable genera: *Sulfitobacter*, *Novosphingobium*, *Bradyrhizobium*, *Desulfoluna*, *Marinobacter*, and *Antarctobacter* each appear multiple times.

### 9.2 Legionella deep dive (`figures/legionella_phac_deep_dive.png`)

*Legionella pneumophila* was the single largest species contributor to §9.1's tail (20/239 genomes, all from the location-blind `RSGB23-1` isolate-genome batch). Since RSGB23-1 genomes are NCBI RefSeq isolate assemblies (not MAGs), they carry something the MAG-derived genomes don't: NCBI's own per-assembly quality metadata, fetched directly for a handful of genomes — a second, independent way to check legitimacy beyond the sequence-level checks above.

**Copy-number matrix** (`figures/legionella_phac_copy_matrix.tsv`, all 66 Legionella genomes): 64/66 are phaC-positive, and within that, **49/51 *L. pneumophila* genomes (96%) carry phaC** — the highest, most consistent species-level prevalence seen anywhere in this project, not a coincidence of a couple of odd genomes. Copy number spans 1–9 across the genus, with two genomes tied for the dataset's maximum (9 copies): `RSGB23-1_GCF-000500125-V1` (*L. pneumophila* "W1046") and `RSGB23-1_GCF-002082905-V2` (*L. anisa* "FDAARGOS_200").

**Those two maximum-copy genomes tell opposite stories — and NCBI's own assembly-quality flags explain why.** GCF_000500125.1 (W1046) is **RefSeq-suppressed for "many frameshifted proteins"**: 440 contigs, N50 only 16.5kb, 36.9% of its annotated genes are pseudogenes, CheckM completeness 66.75%. GCF_002082905.2 (FDAARGOS_200) is the opposite: an FDA-ARGOS reference-quality, PacBio+Illumina hybrid assembly, 4 contigs, N50 4.2Mb, 99.76% complete, only 1.7% pseudogenes, not suppressed. Two more high-copy genomes checked the same way, `L. pneumophila` "GC05" (n=6) and `Legionella sp.` "PC1000" (n=7), are both good/complete assemblies (98.9%/99.7% complete, <2.2% pseudogenes). **Per-target triad-completeness tracks this almost perfectly**: W1046 (suppressed) — 2/9 (22%) truly triad-complete; GC05, PC1000, FDAARGOS_200 (all good assemblies) — 83–89% triad-complete. This was checked manually for 4 of the 27 high-copy Legionella genomes (not automated dataset-wide, though §9.3 below scripts the same core check across the whole multi-copy population), but the pattern is clean enough to trust as a general mechanism: a fragmented, frameshift-riddled assembly inflates apparent phaC copy number with broken gene pieces, not real paralogs.

**Do the proteins form distinct clusters, or overlap? Opposite answers again.** At 70%-identity clustering, W1046's 9 copies fall into only **5 distinct clusters** (some copies are near-duplicates of each other — consistent with fragmentation splitting one real gene into several highly similar pieces); FDAARGOS_200's 9 copies fall into **9 distinct clusters, no two alike** — genuinely diverse paralogs, not redundant fragments.

**Coverage, length, and fragments.** W1046's copies: two are full-length and complete (581aa/596aa, target-coverage 0.97–0.99), the other seven are short (96–529aa, most under 230aa) with low target-coverage (0.15–0.61) — textbook partial/fragmentary ORF calls. FDAARGOS_200's copies: seven of nine are full-length (553–598aa, target-coverage 0.67–1.0, several at 100% identity to their best reference match), only one is short (379aa, low coverage). A neighbor-joining tree built directly from the sequences (pure Biopython pairwise alignment — no external aligner was available in this environment; see script docstring) makes the same split visually obvious: W1046's tree mixes long triad-complete branches with short fragment branches at shallow, ambiguous depths, while FDAARGOS_200's tree cleanly separates genuinely divergent, mostly triad-complete paralogs.

**Genomic location: same story a third way.** W1046's copies sit on five different, mostly single-gene scaffolds (`scaffold_42`, `_193`, `_319`, `_360`, `_370`) — consistent with a fragmented draft assembly where short contigs break genes apart. FDAARGOS_200's copies are almost all on one scaffold (`scaffold_1`, presumably the main chromosome, positions 807–3081 — spread across the genome, not one tight operon, except for three genes at positions 3077/3079/3081 forming a plausible small local cluster), with two more on a separate, smaller `scaffold_3` — worth flagging as a candidate second replicon (plasmid or secondary chromosome piece), though this can't be confirmed without the genome's own NCBI replicon annotation.

**Do high-copy Legionella have larger/more complex PHA pathway architectures overall? Yes, strongly — but likely the same artifact, not coordinated biology.** Across all 64 Legionella genomes, n_phaC correlates with n_phaZ (r=0.87), n_phaA and n_phaB (r=0.75 each), and n_phaJ (r=0.69); high-copy genomes (≥5 phaC, n=27) average 10× more phaA, 16× more phaB, and 5.6× more phaZ than low-copy genomes (≤2 phaC, n=27) — a broad, genome-wide inflation across nearly every PHA gene family at once (phaE, phaG, phaP, phaI, phaM, phaD, phaQ are uniformly absent in this genus regardless of copy number, so the correlation isn't universal). Given the assembly-quality finding directly above, the most parsimonious reading is that a fragmented, frameshift-heavy assembly breaks up *every* gene family's calls proportionally, not just phaC's — this correlation is very likely mostly measuring assembly quality, not real coordinated pha-operon proliferation, though a real component can't be ruled out without checking each gene family's own fragment lengths the way this section did for phaC.

### 9.3 Scripted legitimacy audit, every genome with >2 phaC copies

§9.1 and §9.2's checks (per-target triad-completeness, 70%-cluster distinctness, protein length, contamination, and — for the handful of Legionella isolates checked by hand — NCBI assembly-quality flags) don't scale one genome at a time. This section scripts the four checks that *are* locally computable at scale (no network calls, so the NCBI-suppression check itself isn't included) and runs them against **every genome with n_phaC≥3** (3,176 genomes, 10.1% of the phaC-positive dataset), to get an approximate legit-vs-artifact split before picking specific genomes for further deep-dive figures.

**Method, exactly as scripted** (`figures/scripts/audit_multicopy_phac_genomes.py`):
- **pct_triad_complete** — of a genome's own target_ids (via the corrected NR100 join, not `genome_family_matrix.tsv`'s `n_phaC`, which §9.2 showed can undercount by 5-6× for some genomes), the fraction with `triad_complete=True` in `catalytic_domain/phac_catalytic_triad.tsv`'s own per-target column — the same real per-target signal §9.1's correction established, not the genome-broadcast one.
- **pct_full_length** — fraction of own targets ≥500aa (a deliberately generous floor below the reference set's own median full-length of 563-591aa, meant to catch obvious fragments like §9.2's 96-367aa W1046 pieces without penalizing real length variation).
- **pct_distinct_clusters** — distinct 70%-identity clusters ÷ number of own targets; 1.0 means every copy is a genuinely distinct paralog, well below 1.0 means some copies are near-duplicates of each other (the fragmentation signature §9.2 found in W1046: 5 clusters for 9 copies, vs. FDAARGOS_200's 9 for 9).
- **checkm_completeness / checkm_contamination** — from `phaC_unique_targets_with_metadata_depth.tsv`, available locally for both MAG and isolate genomes. Weaker signal than the three above: confirmed directly that it can disagree substantially with NCBI's own per-assembly figure (W1046 shows 96.0% complete here vs. NCBI's 66.75%) — used only as a contamination gate, not as the primary call.
- **n_phaC_contigs / max_phaC_on_single_contig** — among the subset of a genome's own targets whose `phaC_cluster_sequences.faa` "rep=" example happens to be that same genome (a lower bound, not exhaustive — reported alongside `n_phaC_contigs_known_of` so per-genome trust can be judged): the number of distinct scaffolds those targets fall on, and the largest number found on any one scaffold. Added after §9.4's single-genome case found a real phaE-phaC-phaJ tandem cluster on one contig — these two columns let that pattern (several copies piled on one contig, vs. spread across many) be scanned for across the whole multi-copy population instead of found by chance. Local-only, same as the checks above; for any specific genome shortlisted from this table for a real deep dive, a direct fetch of its own gene calls (as done for §9.4's CARD22-1 genome) resolves the "known_of" gap completely — not done for all 3,176 genomes here, only worth it by hand for whichever few get picked next.

**Composite call** (stated thresholds, not a black-box score, calibrated only against §9.2's two hand-checked extremes — W1046: 0.22 triad/0.56 clusters; FDAARGOS_200: 0.89 triad/1.0 clusters): `likely_legit` if pct_triad_complete≥0.6 **and** pct_distinct_clusters≥0.6 **and** contamination (if known) ≤10%; `likely_artifact` if pct_triad_complete<0.3 **or** pct_distinct_clusters<0.3 **or** contamination >10%; `uncertain` otherwise; `insufficient_data` if triad or cluster data is missing for that genome (rare — coverage was 7,943/7,943 targets for both in this run).

**Result: most multi-copy genomes look legitimate by these checks.** 2,727/3,176 (85.9%) call `likely_legit`, 364 (11.5%) `uncertain`, only 85 (2.7%) `likely_artifact`. Isolate genomes score slightly *better* than MAGs (91% vs. 85% likely_legit) — consistent with §9.2's finding that assembly fragmentation, not binning contamination, is the dominant failure mode, since isolate assemblies vary in contig-level quality too but aren't subject to metagenomic binning error at all. By copy count: 3-4 copies (n=2,897) 86% legit; 5-9 copies (n=276) 83% legit; the 3 genomes with 10+ copies are all `uncertain`. **Read this as an upper bound on the legit fraction, not a final verdict** — the composite call only uses signals cheap enough to run at this scale; §9.2's NCBI-suppression check (the single clearest signal found so far) isn't included, and a small number of `likely_legit` calls could still fail that check the way GC05/PC1000/FDAARGOS_200 passed it and W1046 didn't.

**Files:** `figures/scripts/audit_multicopy_phac_genomes.py`; `figures/phac_multicopy_legitimacy_audit.tsv` (3,176 genomes, one row per genome — no figure, this is a scanning/triage table for picking future deep-dive candidates).

### 9.4 One genome, close up: CARD22-1_SAMN24292811_MAG_00000010 (`figures/card22_desulfoluna_phac_deep_dive.png`)

Picked from §9.3's audit survivors deliberately, not just by raw copy count: an uncultured *Desulfoluna* MAG from Red Sea coral tissue (*Goniastrea edwardsi*, 22.18°N 39.02°E, study CARD22-1) with 7 phaC copies, all 7 in distinct 70%-identity clusters, 99.35% complete / 1.77% contamination, `likely_legit`. A real environmental sample at a specific location with a clean bin — not a location-blind isolate batch (§9.2) or the fragmented-assembly risk §9.2 flagged.

**Do the copies form one clade (recent duplication) or fall into different classes (independent acquisitions)? Clearly the latter.** A neighbor-joining tree (Biopython pairwise BLOSUM62 alignment, no external aligner) splits cleanly into two groups, not one: a Class III-leaning trio and a Class I-leaning quartet. Pairwise %identity across all 7 copies is mostly 26-32% — only two pairs exceed 55% (58%, 67%), both well short of the >90% a recent duplication would show. This genome's phaC expansion reads as accumulated independent acquisitions/divergence, not a recent tandem-duplication event.

**Structural class, from live HMM scoring, not a proxy.** All 6 profile HMMs already used dataset-wide for the HMM-supported evidence tier (Pfam PF07167, this project's own 625-column custom HMM, NCBIFam TIGR01838/1839/1836 for Class I/II/III, PANTHER PTHR36837) were run directly against these 7 sequences with `pyhmmer` (pure-Python, no external binary — the committed `.hmm` files under `phac_recovery/hmm/` are enough), giving real bit scores/e-values per model instead of the binary presence signal used elsewhere. Two copies (both 372-380aa, the pair described next) **officially pass** TIGR01836's own curated trusted cutoff for Class III. Two more score highest on TIGR01838 (Class I) but fall short of *that* model's official cutoff — informative as "Class I-leaning" but not a certified call. The remaining three (the two longest, most divergent copies, and one weak all-around hit) don't clear any class's official threshold.

**Contig map: a real phaE-phaC-phaJ operon.** On `scaffold_12`, three genes sit immediately adjacent, same strand, tight spacing (13bp and 90bp gaps): phaE, then a phaC copy that is one of the two officially-Class-III-confirmed synthases, then phaJ. This is textbook Class III PHA synthase architecture — Class III phaC is a catalytic subunit that functions as a heterodimer with phaE, and this genome (`genome_family_matrix.tsv`) does carry exactly one phaE — plus a beta-oxidation-linked precursor gene (phaJ) right next door. `scaffold_9` carries a second, different pair: a Class I-leaning copy immediately followed by the other officially-Class-III copy — two different classes sitting side by side, not fused, not near-duplicates (28% identity to each other). `scaffold_1` carries two more phaC copies (both Class I-leaning) plus several phaA/phaB genes elsewhere on the same ~1,100-gene scaffold, not physically clustered with either phaC copy. `scaffold_2` and `scaffold_27` each carry one isolated phaC copy with no other pha-family gene nearby on that scaffold (checked directly against this genome's full prodigal gene set, not assumed).

**One finding that qualifies the "7 legitimate copies" headline: two of them may not be phaC at all.** The two longest, most divergent copies (708aa and 736aa — notably longer than this project's own ~560-600aa reference median) are the two that scored weakest across the class-specific HMMs, hitting only Pfam-adjacent signal, and cross-checking against this genome's own independently-computed phaZ-family (depolymerase) candidate table found both score *higher* against their best phaZ match (44.8%, 43.6% identity) than against their best phaC match (39.0%, 41.0%). PhaC and PhaZ share the same alpha/beta-hydrolase fold and catalytic-triad architecture, so this is a real, unresolved ambiguity, not a lookup error — these two are flagged `phaC?` throughout the figure. The other 5 copies show no such ambiguity. Net effect: closer to 5 confidently-phaC copies plus 2 genuinely uncertain ones than a clean 7.

**Provenance note:** the contig positions for the non-phaC pha genes (phaA/B/E/J) required data this repo doesn't cache locally — this genome's own prodigal gene calls and the specific UniProt sequences its own phaA/B/E/J/Z hits were matched to — fetched directly from the OMDB mirror and UniProt for this one genome and recorded as documented constants in the script (same treatment as §9.2's manually-checked NCBI assembly-quality data). The tree, %identity matrix, and structural-class HMM scoring are fully live/reproducible with no network dependency.

### 9.5 A conserved gene family, checked across 6 genomes: Modicisalibacter zincidurans (`figures/modicisalibacter_phac_deep_dive.png`)

Picked for biotechnology/synbio potential, against two explicit criteria: copy count above the ~5-copy literature maximum, and enough sister genomes of the same species to check whether the paralogs are conserved or one-off. Two candidates were compared head-to-head before choosing:

- **`Unknown HK1`** (an unnamed lineage) had a 7-copy genome and 167 phaC-positive sister genomes across 10 studies — looked strong on paper, but the **median** copy count across those 167 genomes is only 2. The 7-copy genome is an outlier for the species, not typical — failed the "median ≥3" bar set before looking.
- **`Modicisalibacter zincidurans`** (Halomonadaceae, Gammaproteobacteria — the same family as *Halomonas bluephagenesis*, an already-commercialized halotolerant PHA-production chassis) has only 6 sister genomes and none above 5 copies, but checking all 6 genomes' phaC target_ids by 70%-identity cluster found **three paralogs present as orthologous clusters in literally all 6 independently-sequenced genomes** (5 different studies plus one NCBI RefSeq isolate reference), each with near-identical %identity-to-reference and length every time it appears (e.g. one paralog is always ~640aa at 75% identity, in every genome that carries it). A 4th paralog appears in 2 of 6 genomes at 97-99% identity. This is about as clean a "real, conserved, species-level gene family" signal as this kind of check produces, and won the comparison outright.

**Species-level pattern isn't full confidence in every copy: two more layers of nuance, both new findings from this genome specifically.** First, live HMM scoring (the same 6 profile HMMs as §9.4, via `pyhmmer`) found a real disagreement between signals: the paralog with the strongest reference-identity match in every genome that carries it (738aa, 69-75% identity) scores weakly on every TIGRFAM class model and has **no Pfam PF07167 hit at all** — reference-identity confidence and structural-HMM confidence do not always agree, and this is flagged directly rather than picking one signal to trust silently. Second, the pan-genome-universal paralog (present in all 6 genomes, ~561aa) scores comparably-to-higher against this genome's own phaZ (depolymerase) candidates (44.5%/46.1%) than against phaC references (43.5%/43.9%) — the same phaC-vs-phaZ ambiguity §9.4 found in the CARD22-1 genome, here affecting the *most conserved* paralog, not a rare fragment. Net picture: of the 3 universally-conserved paralogs, one is confidently phaC (Class I, passes the official trusted cutoff), one is confidently phaC by reference identity but structurally atypical, and one is genuinely ambiguous phaC/phaZ despite being present in every genome checked.

**Contig map: a real phaB-phaA-phaB-phaB-phaA-phaC gene cluster.** Fetching this genome's own gene calls directly (same one-off, documented method as §9.4 — this genome's `.genes.faa.gz` from the OMDB mirror, UniProt sequences for its own phaA/phaB/phaZ hits, searched with `pyhmmer` against just the genes on its two phaC-bearing scaffolds) found a dense, ordered run of phaB, phaA, phaB, phaB, phaA, then two phaC copies, all within a ~13-gene window on one scaffold — the canonical PHA-biosynthesis arrangement (phaA+phaB build the precursor, phaC polymerizes it) sitting together as one physical unit. That is exactly the shape of gene cluster that is easiest to move into a heterologous host as a single operon, which is the concrete link back to the synbio-potential framing this genome was picked for.

### 9.6 Rebuilt the ESMFold "uncertain" input set around what §9.1–9.5 actually found uncertain

§6's original `structure_prediction/uncertain_cluster_representatives.faa` (4,992 sequences) was built against the pre-fix tier definitions and marked STALE there — the "no direct evidence" tiers it sampled from collapsed to 27 genomes total after the 2026-09-22 phaC fix, so almost none of those 4,992 sequences still correspond to anything genuinely uncertain about this dataset. Replaced with a 605-sequence, hand-picked set (`structure_prediction/build_uncertain_set_v2.py`) built from five sources, each tied to a specific open question raised in §9.1–9.5 rather than a broad generic sample:

1. **Modicisalibacter zincidurans** — all 10 distinct phaC target_ids across all 6 sister genomes (§9.5). Includes the paralog confidently phaC by reference identity but structurally atypical on every TIGRFAM class HMM (738aa) — exactly the case a folded structure can help resolve where sequence HMMs did not.
2. **Desulfoluna (CARD22-1 study)** — all 8 distinct target_ids across both CARD22-1 genomes (§9.4), including the two phaC/phaZ-ambiguous copies (708aa/736aa).
3. **"Unknown HK1"** — all 330 distinct target_ids across all 167 phaC-positive genomes of this species (§9.5's runner-up candidate, still worth resolving structurally given its size and sponge-symbiont prevalence).
4. **The 26 distinct targets behind §3's two smallest evidence tiers** ("No HMM/triad, ≥5 other PHA genes" + "1-4 other PHA genes", 27 genomes total) — pathway-context evidence only, zero direct sequence evidence. Small enough now to fold every member rather than sample.
5. **273 targets dataset-wide with <50% identity to their nearest non-self phaC** in the all-vs-all self-search (264 with a resolved hit below 50%, plus 9 with no self-hit at all even at the loose e-value cutoff used — the most extreme form of divergent). Same self-search table and re-filtering discipline as §7's/§9's divergent35 table, at 50% instead of 35% and applied per-target rather than one representative per genome, since the goal is folding specific proteins, not a genome-level count.

6 targets are shared across more than one source (mostly divergent-and-HK1 or divergent-and-no-support overlaps) — real convergent evidence, not double-counting, since the FASTA and manifest both dedupe to one row per target_id (`uncertain_set_v2_provenance.tsv` records every source that flagged each one).

**Length filter, applied deliberately unevenly.** The project's usual 150-700aa fragment filter is applied to sources 4-5 (where it serves its original purpose of excluding likely-unfoldable fragments from a generic scan) but *not* to sources 1-3, which are hand-picked, already-investigated candidates — 3 of them (the CARD22-1 708aa/736aa pair, the Modicisalibacter 738aa paralog) are over 700aa specifically because their unusual length is part of why they are worth a fold, and the 150aa floor is still applied everywhere (a fold from under 150 residues isn't structurally interpretable regardless of how the candidate was picked). Final set: 152-741aa, median 475aa, 7 sequences over 700aa kept on purpose.

`structure_prediction/fold_manifest.tsv`'s 428 `positive_control` and 1,875 `reference` rows (already built and not touched by this rebuild) are carried over unchanged; only its 4,992 `uncertain` rows were replaced with the new 605. `cluster/run_esmfold.sbatch`'s sizing guidance updated accordingly (try `N_BATCHES=6`, down from 40).

## 10. Does phaC cluster identity pair with precursor route?

If a phaC synthase's substrate arrives via a different upstream pathway (FAS-linked vs. beta-oxidation-linked), that is a plausible source of real selective pressure on the synthase itself — a testable version of "the phaC structure should pair up with these proteins." `figures/scripts/plot_phac_cluster_vs_precursor_route.py` asks this directly: within a phaC_cluster0.7 cluster (70%-identity group), is %phaG elevated or depleted relative to baseline, after controlling for phylum?

**Rebuilt 2026-09-22 with a real bug fixed, and the fix mattered enormously — not just for the numbers, but for the strength of the finding.** This script had no reference-query filtering at all on either side of its raw NR100 cluster-membership join (found while re-examining it for this rebuild, the same class of bug as §7's) — meaning the "does this genome have exactly one phaC target_id" check was being evaluated against uncorrected data, which could make a genuinely single-copy genome look multi-copy (and wrongly excluded) or count a now-excluded target as if it were real. Fixed by filtering both sides against the current 219-accession bad-target list.

**Restricted to single-copy genomes only, and restricted further to genomes where two independent pipelines agree on that copy count** (§9's `n_phaC==1` vs. exactly one surviving target_id in the corrected NR100 join). With the filtering bug fixed, the analysis set is now **17,398 genomes (55.3% of all phaC-positive genomes)** — up sharply from a broken intermediate run of just 3,375 genomes, and actually a *larger share* of the dataset than the pre-fix version of this analysis achieved (35.3%), because the bug had been artificially inflating the pipeline-disagreement count throughout. Baseline %phaG in this restricted set is 3.90%.

**The pairing signal came through far more strongly once the genomes that belonged in this analysis were actually included.** Of 98 clusters with ≥30 single-copy genomes (up from 131 in the pre-fix run, on a very different and now-correct genome pool), phylum-controlled CMH finds **15 significantly elevated for phaG and 19 significantly depleted** (p<0.05) — roughly 3× as many significant elevated hits as before. The top result is dramatic: cluster `...035112905` (34 genomes, 100% Pseudomonadota) is **79.4% phaG-positive** — against a Pseudomonadota-wide baseline around 5-6% (§8) — a **93.7× phylum-controlled odds ratio (p=1.0×10⁻¹⁰⁸)**, nearly triple the strongest odds ratio found in the pre-fix run. Several more large, strong hits follow: cluster `...070874498` (142 genomes, 96.5% Pseudomonadota) at 38.0% phaG (OR 14.9, p=1.8×10⁻⁸³), `...244652500` (45 genomes, 100% Pseudomonadota) at 28.9% (OR 9.6, p=7.3×10⁻¹⁷), and `...242079509` (39 genomes, 100% Pseudomonadota) at 28.2% (OR 9.2, p=4.4×10⁻¹⁴). This is now a considerably more convincing version of the pairing hypothesis than the pre-fix result: specific phaC sequence variants are disproportionately associated with the FAS-linked route *within their own phylum*, across more clusters, with stronger effect sizes, once the analysis was actually run on the genomes it was supposed to include. Full results, every qualifying cluster, in `figures/phac_cluster_precursor_route_all_clusters.tsv`.

**Caveat on scope:** this is a real finding about the 55.3% of phaC-positive genomes where pairing is unambiguous, not a claim about the whole dataset — the remaining genomes (multi-copy, or with pipeline disagreement) are structurally excluded from this specific question, not because anything is wrong with them.

**Files:** `figures/scripts/plot_phac_cluster_vs_precursor_route.py`; `figures/phac_cluster_vs_precursor_route.png`/`.pdf`, `figures/phac_cluster_precursor_route_all_clusters.tsv`.
